# 🐱 Мемный Кот: Империя Мяумонет

Браузерная игра в жанре Clicker/Tycoon, реализованная по техническому заданию
на C# / .NET / ASP.NET Core с Clean Architecture и CQRS.

---

## 1. Описание игры и выбранный мем

Тема — **мемный кот-блогер**. Игрок начинает с обычного дворового кота и
превращает его в мемную интернет-империю: сначала гладит кота вручную,
затем автоматизирует процесс, нанимает ботов-подписчиков и открывает
собственную студию.

Главный ресурс — **МяуМонеты** 🐾. Основное действие — кнопка
**«Погладить кота»**.

## 2. Core Loop

```
Погладить кота → получить МяуМонеты → купить улучшение →
   изменение механики/эффективности → накопить ресурс до порога →
   открыть новый этап → новые улучшения и события → повторить
```

Игрок всегда видит на экране: сколько ресурса за клик, сколько ресурса
в секунду даёт автоматизация, шанс крита, прогресс до следующего этапа
и стоимость каждого улучшения.

## 3. Экономика

Все параметры экономики (стоимость улучшений, рост цены, шансы событий,
длительность бустов и т.д.) вынесены в конфигурационный файл
[`src/ClickerTycoon.Api/gameconfig.json`](src/ClickerTycoon.Api/gameconfig.json)
и **не захардкожены** в игровой логике — сервер читает их один раз при
старте (`IGameConfigProvider`).

- Стоимость улучшения растёт по формуле `BaseCost * CostGrowth^level`.
- Автоматический доход считается «лениво»: при каждом запросе к серверу
  (клик или опрос состояния) вычисляется, сколько времени прошло с
  последнего тика, и начисляется доход за это время (с ограничением
  `MaxOfflineSeconds`, чтобы нельзя было получить бесконечный доход,
  вечно не заходя в игру).
- Мгновенно скупить всё содержимое нельзя: цены растут экспоненциально,
  а часть улучшений и все три события заблокированы до нужного этапа.

## 4. Улучшения (7 штук, из них 4 меняют механику)

| Улучшение | Эффект | Меняет механику |
|---|---|---|
| 🐾 Чешутся лапки | +20% к доходу за клик / уровень | — |
| 😻 Мурчание | +1 к клику (плоский бонус) / уровень | — |
| 🥫 Автокормушка | +2 ресурса/сек автоматически | ✅ вводит автоматизацию |
| 📰 Кликбейт-заголовок | +3% к шансу крита / уровень | ✅ вводит критические удары |
| 🤖 Боты-подписчики | +15% к авто-доходу / уровень (этап 2) | ✅ усиливает автоматизацию |
| #️⃣ Вирусный хэштег | +0.8% к шансу вирусного события (этап 2) | ✅ влияет на события |
| 🎬 Профессиональная студия | +50% к доходу за клик (этап 3) | — |

## 5. Этапы развития (3 штуки)

1. **Дворовый кот** — только ручные клики и базовые улучшения.
2. **Интернет-знаменитость** (нужно 1000 ресурса + улучшение
   «Автокормушка») — открывается автоматизация, новые улучшения и
   случайные события.
3. **Мемная империя** (нужно 50 000 ресурса + улучшение
   «Боты-подписчики») — самые дорогие и мощные улучшения.

## 6. События (3 типа, все влияют на игровой процесс)

- **Позитивное — «Мем завирусился!»**: доход x3 на 30 секунд.
- **Кризис — «Алгоритмы решили, что ты больше не в тренде»**: доход
  снижен (x0.4) до тех пор, пока игрок не сделает N кликов подряд
  (событие, зависящее от действий игрока).
- **Мемный поворот — «Кот украл аккаунт»**: игрок теряет часть
  накопленного ресурса, но получает временный бонус x2.

Все три события случайны, но их шанс выпадения (`*ChancePerClick`) и
кулдаун (`MinClicksBetweenEvents`) настраиваются в `gameconfig.json`;
некоторые улучшения («Вирусный хэштег») сами по себе влияют на шанс
события — то есть события частично зависят и от выбора игрока.

## 7. Монетизация (3 концепции, полностью симулированные)

1. **Rewarded Ads** — кнопка «Посмотреть рекламу» → x2 доход на 60 секунд.
   Реального показа рекламы нет, эффект применяется сразу.
2. **Premium Upgrade** («Premium Camera») — разовая условная покупка,
   даёт постоянный +25% к доходу за клик.
3. **Starter Pack** («Мемный стартовый набор») — разовая условная
   покупка: мгновенно +500 ресурса и временный буст x1.5 на 60 секунд.

Все три находятся в блоке **«Монетизация»** на главном экране,
отмечены бейджем «симуляция» и не требуют реальной оплаты — сервер
просто помечает офер как купленный/активный.

## 8. Архитектура и стек

**Backend:** C# / .NET 8 / ASP.NET Core, **Clean Architecture + CQRS**.

```
ClickerTycoon.Domain          — сущности, конфигурация игры, GameCalculationEngine
                                 (вся игровая математика: клики, улучшения,
                                 события, авто-доход, этапы) — без внешних зависимостей
ClickerTycoon.Application     — команды/запросы (CQRS), DTO, интерфейсы
                                 репозитория/конфига/времени/рандома
ClickerTycoon.Infrastructure  — EF Core + SQLite, JSON-конфиг, системные часы/рандом
ClickerTycoon.Api             — ASP.NET Core Web API (контроллеры),
                                 middleware обработки ошибок, статический frontend
ClickerTycoon.Tests           — xUnit-тесты домена и обработчиков команд
```

CQRS реализован собственным лёгким диспетчером
(`Application/Common/Cqrs/Cqrs.cs`) — команды (`ICommand`) и запросы
(`IQuery`) обрабатываются раздельными обработчиками, без сторонних
библиотек-медиаторов.

**Frontend:** обычные HTML + CSS + vanilla JS (без сборки/бандлера),
раздаются как статические файлы из `ClickerTycoon.Api/wwwroot`.
Фронтенд не содержит игровой логики — он только вызывает внутренний
REST API (`/api/players`, `/api/game/{id}`, `.../click`,
`.../upgrades/{id}`, `.../monetization/{id}`, `.../reset`) и отображает
то, что вернул сервер. Клиент не может напрямую задать количество
ресурса или стоимость покупки — всё проходит через доменную логику на
сервере.

Внизу страницы есть кнопка **«Сбросить прогресс»** (с подтверждением) —
она вызывает `POST /api/game/{id}/reset`, который полностью обнуляет
сохранение в базе данных (ресурс, улучшения, этап, эффекты, покупки
монетизации), сохраняя тот же идентификатор игрока.

## 9. Хранение данных

Прогресс хранится в **SQLite** (`clickertycoon.db`, создаётся
автоматически рядом с проектом `ClickerTycoon.Api` при первом запуске
через `Database.EnsureCreated()` — отдельная миграция не требуется).

Игрок identифицируется `Guid`, который сервер выдаёт при первом визите
(`POST /api/players`). Браузер хранит **только этот идентификатор** в
`localStorage`, а не игровое состояние — само состояние (ресурс,
улучшения, этап, активные события, покупки монетизации) целиком лежит
в базе данных на сервере, как и требуется по заданию.

## 10. Как запустить в Rider

1. Убедитесь, что установлен **.NET 8 SDK**.
2. Откройте `ClickerTycoon.sln` в Rider (File → Open).
3. Rider сам восстановит NuGet-пакеты при загрузке решения.
4. В списке конфигураций запуска выберите **ClickerTycoon.Api** и
   нажмите Run (▶ / Shift+F10).
5. При первом запуске автоматически создастся файл базы данных
   `clickertycoon.db` рядом с проектом `ClickerTycoon.Api`, и в браузере
   откроется `http://localhost:5266`.

Через терминал, без Rider:

```bash
dotnet restore
dotnet run --project src/ClickerTycoon.Api
```

Запуск тестов:

```bash
dotnet test
```

или через Rider: правый клик по проекту `ClickerTycoon.Tests` →
**Run Unit Tests**.

## 11. Конфигурация

Экономику можно менять без изменения кода — правьте
`src/ClickerTycoon.Api/gameconfig.json`:

- `BaseClickValue`, `BaseCritChance`, `CritMultiplier` — базовые
  параметры клика;
- `Upgrades[]` — список улучшений (стоимость, рост цены, эффект,
  требуемый этап);
- `Stages[]` — этапы развития и требования для перехода;
- `Events` — шансы, длительность и сила всех трёх событий;
- `Monetization` — параметры трёх монетизационных офферов.

После изменения файла достаточно перезапустить `ClickerTycoon.Api`.

## 13. Известные ограничения / компромиссы

- Автоматический доход считается «лениво» (по разнице времени между
  запросами), а не отдельным фоновым воркером на игрока — это
  осознанное упрощение, чтобы не плодить лишнюю инфраструктуру для
  учебного прототипа; на игровой результат это не влияет.
- Если несколько активных бустов накладываются друг на друга во время
  простоя (авто-тика), их множители применяются ко всему прошедшему
  интервалу целиком, а не «по кусочкам» — небольшое упрощение расчёта,
  не влияющее на баланс на практике.
- Регистрации и авторизации нет (по ТЗ это не требуется) — игрок
  идентifицируется случайным `Guid`, который выдаётся при первом визите.
- Реальных платежей и рекламы нет — все три модели монетизации полностью
  симулированы на сервере.
- Frontend — vanilla HTML/CSS/JS без сборки, чтобы решение запускалось
  одним `dotnet run` без дополнительных шагов сборки клиента.
